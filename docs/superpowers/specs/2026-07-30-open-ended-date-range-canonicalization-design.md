# 开放日期区间标准化设计

## 背景与目标

当前导入能够识别 `2018-06至今`，并正确产生 `start_date=2018-06`、
`end_date=至今`，但组合文本被标准化为 `2018-06至今`。闭区间已经使用
`2018-06—2020-05`，开放区间缺少同一连接符，显示、详情和重建 Excel 的格式不一致。

本次将开放日期区间的唯一标准组合文本调整为：

```text
2018-06—至今
```

输入兼容性保持不变，不要求用户先修改原工作簿。

## 输入与输出合同

以下现有明确输入都继续接受：

- `2018-06至今`
- `2018-06-今`
- `2018-06—至今`
- `二〇一八年六月至今`
- 使用“今”或“现在”作为结束标记的既有合法区间

所有输入统一产生：

- `start_date=2018-06`
- `end_date=至今`
- `end_date_year/end_date_month/end_date_day=NULL`
- 组合文本 `2018-06—至今`

模糊起点、缺失起点、多段区间、无效日期和无法唯一切分的文本继续拒绝。不会为来源中
缺失的月或日补值。

## 版本边界

`SourceValueParserV1/V2`、`SourceValueNormalizerV3` 和 Flyway V10–V13 保持冻结，
不修改已发布迁移的解释规则或校验和。

当前导入边界 `SourceValueNormalizerV4` 在复用 V3 完成端点识别、精度校验和闭区间标准化后，
只调整“结束端为至今”的组合文本：在标准起点和 `至今` 之间加入一个中文长横线 `—`。
起止端点对象保持不变。

## 新导入数据流

1. `ExcelArchiveReader` 继续把主要学历、工作经历等重复区段交给 V4。
2. V4 继续兼容 `--`、`---`、`～`、`——` 及原有单连接符。
3. V3 解析并校验起点与结束标记。
4. V4 把开放区间组合文本统一为 `起点—至今`。
5. `SnapshotWriter` 持久化相同的 `start_date`、`end_date`、数字投影和新组合文本。
6. 详情接口和 Excel 重建继续原样读取数据库组合文本，不增加查询时二次格式化。

## 已有活动档案迁移

新增 MySQL 与 KingbaseES 的 Flyway V14 Java 入口，共用一份数据库无关迁移实现。
迁移仅处理：

- 活动人员快照下 `pa_education.education_type='MAIN'` 且 `end_date='至今'` 的行；
- 活动人员快照下 `pa_work_experience.end_date='至今'` 的行。

迁移根据已标准化的 `start_date`、`end_date` 和非日期文本重建 `raw_text`，将
`2018-06至今\t说明` 更新为 `2018-06—至今\t说明`。它不修改：

- `start_date`、`end_date` 及其数字投影；
- 排序、人员版本关系、审计或导入历史；
- 已软删除人员快照及其子表历史内容；
- 其他日期字段和闭区间。

Flyway 事务保证 MySQL 或 KingbaseES 上迁移失败时不留下半完成结果。迁移不输出业务原文。

## API、客户端与导出

API 字段仍是字符串，OpenAPI 和客户端类型不变。详情页面会自然显示新的组合文本；导出端
继续把数据库 `raw_text` 写回模板，因此活动档案迁移后，已有档案重新导出的 Excel 也显示
`2018-06—至今`。无需修改 Electron 页面或空白 Excel 模板。

## 测试与验收

实现按 TDD 顺序进行：

1. V4 单元测试先期望 `2018-06至今` 等输入输出 `2018-06—至今`，确认当前代码红灯；
2. 真实模板读取测试验证工作经历单元格、`raw_text`、起止字段和投影；
3. MySQL V13→V14 迁移测试验证活动学历/工作行被统一，软删除历史保持原样；
4. KingbaseES 静态契约测试验证 V14 位于生产 Flyway 路径并调用同一共享实现；
5. 查询与导出既有测试更新为新的标准文本；
6. 执行定向测试、完整 `./mvnw verify` 和只读工作簿解析；
7. 重启后端并检查后端、Vite、Electron 和 MySQL 健康状态。

完成标准是新导入与已有活动档案都使用 `起点—至今`，冻结版本未修改，软删除历史不变，
所有相关验证均有实际工具输出。

## 非目标

- 不改变“至今”的数据库结束端标记；
- 不把“至今”转换为当前日期；
- 不重新计算已经存储的年龄或日期；
- 不修改软删除历史快照；
- 不增加日期筛选、排序、统计或管理页面。
