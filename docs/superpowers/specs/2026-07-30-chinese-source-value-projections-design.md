# 中文年龄与日期结构化投影设计

> **状态：已被 V13 标准化合同取代。** 本文记录 V9/V10 投影阶段的历史决定，不再是当前导入行为。当前精确非空年龄和日期由 `SourceValueNormalizerV3/V4` 同时规范化文本与投影；`三十多岁` 等模糊非空值会返回字段级失败，而不是保留原文并写入空投影。权威合同见仓库 `AGENTS.md` 和 OpenAPI。

## 历史产品决定（V9/V10）

Excel 中的来源原文继续是展示、接口返回和重建工作簿的唯一权威值；在此基础上，为能够明确解释的年龄和日期额外保存结构化数字投影。

| Excel 来源值 | 原文列 | 结构化投影 |
|---|---|---|
| `三十五岁` | `三十五岁` | 年龄 `35` |
| `35岁` | `35岁` | 年龄 `35` |
| `二〇二四年五月` | `二〇二四年五月` | 年 `2024`、月 `5`、日 `NULL` |
| `二〇二四年五月三日` | `二〇二四年五月三日` | 年 `2024`、月 `5`、日 `3` |
| `二〇二四年` | `二〇二四年` | 年 `2024`、月和日 `NULL` |
| `三十多岁` | `三十多岁` | 年龄 `NULL` |

结构化投影只表达来源文本中能够确定的事实：不得把年补成一月一日，不得把年月补成当月一日，不得从出生日期推算年龄，也不得把模糊年龄猜成某个数字。无法确定的投影保持 `NULL`，但原文照常保存和导出。

## 解析边界

新增版本化深模块 `SourceValueParserV1`，把第三方库差异、中文数字语法和 Java 日期校验封装在一个接口后。V1 一旦被 Flyway 历史回填迁移使用即视为不可变；未来若要改变解释规则，应新增 V2 解析器和新的迁移，而不是修改 V1 的既有语义。

模块接受以下输入：

- 年龄：阿拉伯数字或可精确解释的中文整数，可带 `岁` 或 `周岁`；例如 `35`、`35岁`、`三十五岁`。
- 日期：年、年月、年月日三种精度；兼容现有数字分隔符，也接受 `二〇二四年五月三日` 这类中文写法。
- 年份：四位逐字数字（如 `二〇二四`、中阿拉伯数字混写）逐位转换；带十、百、千单位的完整整数交给 Hutool 转换。
- 月、日和年龄：中文计数数字交给 Hutool `NumberChineseFormatter.chineseToNumber`，结果再由本系统执行整数、范围和日期合法性校验。
- 日期区间：保留现有 `-`、`—`、`–`、`~`、`至` 分隔及 `至今`、`现在`、`今` 结束标记，区间两端仍保留各自原文和精度。

解析使用一份去除空白、完成 Unicode NFKC 归一化的副本；返回对象中的原文仍是读取层已经取得的来源文本，不能用归一化副本覆盖。`Year`、`YearMonth`、`LocalDate` 负责年份、月份和真实日历日期校验。

以下年龄故意不生成数值：`三十多岁`、`约三十岁`、`三十五岁半`、范围、负数及超出 `SMALLINT` 非负范围的数字。以下日期继续判为非法并在导入时返回安全的单元格坐标：不存在的月、日或不完整的中文单位表达。

## 第三方依赖

只引入固定版本 `cn.hutool:hutool-core:5.8.46`，不引入聚合包 `hutool-all`。

Hutool 负责已经成熟的中文计数数字转换；项目代码只负责 Hutool 不处理的四位年份逐字语法、字段拆分、精度保留和 `java.time` 校验。这一边界既减少自写数字算法，也避免依赖 Hutool 的通用日期猜测改变档案语义。

## 领域和导入

`SourceDate` 继续携带来源文本和精度对应的 `Year`、`YearMonth`、`LocalDate`，但这些对象现在除了校验，也用于生成数据库数字投影。它们永远不能反向格式化或替换来源文本。

`ExcelArchiveReader` 的标量日期、家庭辅助日期、声明日期和重复行日期区间统一调用 `SourceValueParserV1`：

- 标量和已关联的家庭出生日期若非空却无法解释，继续以 `TEMPLATE_INVALID` 拒绝该文件；
- 重复行仍以 `raw_text` 为重建依据，只有能明确解释的日期片段才生成投影；
- 家庭年龄先按现有规则取得字面原文或标准 `DATEDIF` 的冻结结果，再独立生成 `age_value`；
- 不执行其他公式，不改变家庭辅助表证据关联规则。

## 数据库模型

Flyway V9 为十二个现有业务日期原文列分别增加三个可空数字投影：`*_year SMALLINT`、`*_month TINYINT/SMALLINT`、`*_day TINYINT/SMALLINT`。MySQL 使用 `TINYINT` 保存月、日，KingbaseES 使用 `SMALLINT` 保持兼容。家庭成员表另加 `age_value SMALLINT NULL`。

约束要求：

- 月存在时年必须存在，日存在时月必须存在；
- 年为 `1000..9999`，月为 `1..12`，日为 `1..31`；
- 年龄非负；
- 无法解析时所有相关投影为 `NULL`。

应用层用 `java.time` 保证如 2 月 30 日这类组合不会写入；数据库范围约束作为第二道防线。暂不增加索引，因为本次只建立可靠存储能力，没有新增结构化年龄/日期查询接口。

Flyway V10 使用不可变的 V1 解析语义回填已有原文。回填只更新新增投影列，不修改任何原文列、`raw_text`、排序、快照关系或审计数据；不能确定的历史值保持 `NULL`。MySQL 和 KingbaseES 各有一个很薄的 Java migration 入口，共用同一份 JDBC 回填实现，并用固定校验和锁定迁移版本。

## 持久化接口

`PersonMapper` 使用小型 `DateProjection` 和 `AgeProjection` 参数对象，避免每个插入方法暴露大量松散整数。`SnapshotWriter` 在一个边界内将 `SourceDate` 或年龄原文转换为这些投影，同时传入原文：

- 根人员、任职、学历、工作经历、奖惩和家庭出生日期都写入原文及年/月/日；
- 家庭年龄写入 `age_text` 及可空 `age_value`；
- 空原文保存为现有 `NULL` 语义；
- 查询 Mapper、详情 DTO、OpenAPI 和客户端不增加投影字段。

## API、展示和导出

这次不改变对外接口。详情 API、列表、搜索和 Excel 重建仍只读取原文列；客户端继续直接展示用户填写的字符串。结构化数字是后端内部数据，为以后经过明确产品设计的筛选、统计或排序提供基础，不能悄悄改变当前展示。

因此无需修改客户端类型，也不会出现 `二〇二四年` 被显示成 `2024-01-01` 或 `三十五岁` 被改写成 `35` 的情况。

## 验证

- 解析单元测试覆盖中文/阿拉伯/混合数字、三种日期精度、闰年、非法日期、精确和模糊年龄、日期区间与至今标记。
- Excel 读取测试确认中文日期可导入且原文不变，模糊年龄不导致文件失败。
- 快照写入测试捕获 Mapper 参数，核对原文和投影同时写入。
- MySQL 8.4 迁移测试先迁到 V9，插入历史原文，再执行 V10，核对可确定值回填、模糊值留空和原文未变。
- KingbaseES 静态契约测试核对 V9 字段、类型和约束；当前本地环境没有 KingbaseES 实例，因此不宣称完成其真实运行时迁移验证。
- 完整导入集成测试同时核对数据库投影、详情 API 原文和重建 Excel 原文。

## 非目标

- 不新增年龄或日期筛选、排序、统计接口。
- 不把投影返回给客户端。
- 不从身份证、出生日期或当前日期推导年龄。
- 不修正用户原文，不执行模糊推断，不修改上传工作簿。
- 不把 Hutool 用作通用日期解析器，也不引入其他基础设施。
