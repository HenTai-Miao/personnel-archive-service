# 标签锚定的历史工作簿兼容导入设计

## 背景与目标

现有 V1 读取器同时把字段坐标、区块起止行、合并区域和家庭成员上限写死。历史工作簿虽然仍使用同一组中文标签，却会因为区块行数不同而移动“奖惩情况”“重要社会关系、家庭主要成员及”和声明区域；家庭成员还可能超过六人。结果是内容有效的工作簿在读取数据之前就被固定坐标或合并区域校验拒绝。

本次改造的目标是让同一业务模板的历史布局按语义标签读取：用户填写什么就导入什么，空白保持空白，不猜测、不补造数据。五份用户工作簿必须能通过正式上传流程进入数据库，页面能够展示全部家庭成员。

## 方案比较

### 方案一：为每种历史版式增加固定坐标版本

每遇到一种行号组合就添加 V1.1、V1.2 等坐标表。它能保持严格校验，但维护成本随版式数量线性增长，未知历史表仍会失败，也无法自然支持任意家庭成员行数。

### 方案二：按行号和相似文字进行宽松猜测

在固定坐标附近搜索近似标签，再按行序关联主表和辅助表。实现较快，但姓名或称谓不一致时容易把出生日期写给错误成员，不符合“空白就是空白”的产品决定。

### 方案三：精确标签锚定与证据化关联（采用）

先对标签做换行、空白和中英文冒号规范化，再要求已知标签精确且唯一出现。单值字段从标签右侧的值单元格读取；重复区块由相邻区块标签确定边界。家庭出生日期只接受工作簿公式引用或规范化后的“称谓＋姓名”完全一致这两类证据。这个方案兼容行号变化，同时不会对业务值做模糊猜测。

## 结构识别

读取器仍要求工作簿包含 `基本情况` 和 `家庭成员年龄计算` 两张表，并保留 ZIP、文件大小、图片类型和图片锚点安全检查。它不读取命名范围，也不因损坏的 `#REF!` 命名范围失败。

主表分为两类区域：

- 顶部单值区域：在受限的顶部范围内查找姓名、性别、出生年月、民族、籍贯、出生地、政治面貌、参加工作时间、任职单位及部门、职务、职称/技能、身份证号、婚姻状况、健康状况、通信地址、邮政编码和电话等精确标签，再读取相邻值单元格。
- 重复区块：依次查找“主要学历”“工作经历”“奖惩情况”“重要社会关系、家庭主要成员及”以及声明文字。前一个标签到后一个标签之间就是该区块的候选行；只导入实际存在用户值的行。

主表和辅助表不再要求固定区块合并区域完全一致。结构校验改为要求关键标签存在、唯一且顺序正确，家庭表头必须在同一行包含“称谓”“姓名”“年龄/出生年月”“政治面貌”“工作单位及职务”等对应列。

## 值读取与空值规则

- 任何业务字段都允许为空；空单元格映射为 `null` 或空文本，不抛出模板错误。
- 年月字段接受 Excel 日期值以及 `yyyy.M`、`yyyy/M`、`yyyy-M`、`yyyy年M月` 文本。数据库仍使用 `DATE`，月份语义使用当月第一日作为内部规范值，导出按模板的年月格式显示。
- 教育、工作和奖惩行保留原始左右文本与制表符边界；额外分布在值区域内的非空单元格也纳入原文，避免只读取一个固定单元格。
- 家庭成员以主表数据行为准。工作单位及职务读取该表头覆盖的完整值区域，而不是只读取 F 列。
- 声明签名和日期从动态声明区域读取，不再固定读取 `B46`。

## 家庭成员出生日期关联

主表家庭行按出现顺序形成成员记录，数量不设业务上限。辅助表行只用于提供出生日期，不单独创建第二组家庭成员。

关联按以下顺序执行：

1. 如果主表年龄单元格公式明确引用 `家庭成员年龄计算!D<n>`，使用该辅助行的出生日期。
2. 否则，在尚未使用的辅助行中查找规范化后“称谓＋姓名”完全相同且唯一的记录。
3. 没有证据时保持该主表成员出生日期为空。不得按剩余项、相同行号、年龄或模糊姓名强行关联。

辅助表日期为空时，关联后的出生日期仍为空。辅助表中没有被任何主表成员引用或精确匹配的行视为计算辅助残留，不写入家庭成员表，也不使导入失败。

## 持久化与数量

移除应用层 `FAMILY_MEMBER_CAPACITY = 6` 校验，并通过新的 Flyway 迁移删除 `pa_family_member.sort_order BETWEEN 1 AND 6` 约束。排序号仍必须为正数，且 `(tenant_id, person_id, sort_order)` 保持唯一。

学历、工作经历和奖惩的现有数据库上限不在本次产品决定内；五份目标工作簿的实际非空数据没有超过这些上限。

## 导出兼容

导入超过六名家庭成员后，现有档案导出不能退化为失败或截断。导出器在生成工作簿时按需要扩展主表家庭成员区和辅助表行数，复制模板行高、单元格样式及合并区域，并把声明区和分页位置整体下移。所有家庭成员按数据库排序写入，空出生日期保持空白。

## 错误处理

- 缺少工作表、关键标签缺失/重复、区块顺序错误、家庭表头缺失或图片越界仍返回 `TEMPLATE_INVALID`。
- 日期单元格非空但无法解析时返回包含安全单元格坐标的日期格式错误；不返回单元格内容。
- 一个工作簿失败不回滚同批次的其他文件。
- 迁移失败、数据库约束冲突或导出扩展失败必须保持现有事务和稳定错误码，不做部分写入。

## 验证策略

采用测试驱动实现：

- 合成历史布局工作簿，先证明旧读取器因区块移动失败，再验证标签锚定后读取成功。
- 合成十名家庭成员，验证全部解析、写库和查询，且空出生日期保持空。
- 构造公式引用、精确姓名称谓匹配和无证据三种家庭关联，验证优先级及“不按剩余项强配”。
- 验证年月文本、跨多格工作单位及职务、动态声明行和损坏命名范围。
- Flyway/Testcontainers 验证第十名家庭成员可以写入；Docker 不可用时明确报告跳过，最终本地 MySQL 实际导入补足验证。
- 导出十名家庭成员后重开工作簿，检查顺序、出生日期空值、扩展合并区域、声明位置和照片。
- 最后通过正式登录与批量上传 API 导入五份用户工作簿，核对五个导入项目均为成功、数据库家庭成员数量分别符合来源，并在 B 客户端的永久导入历史和人员档案页面展示结果。

## 非目标

- 不新增家庭成员核对弹窗。
- 不把辅助表残留行强制合并到主表成员。
- 不保留上传源工作簿，也不在日志、测试夹具或提交中加入真实人员数据。
- 不改变重复档案的 `OVERWRITE`/`SKIP` 产品流程和权限模型。
