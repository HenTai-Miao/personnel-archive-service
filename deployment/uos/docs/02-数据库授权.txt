人员档案数据服务——MySQL 应用账号授权
======================================

项目首次启动需要 Flyway 在 personnel_archive 库执行 V1—V15，日常业务也要读写该库。
若应用账号没有库级权限，服务会在数据库连接或 Flyway 阶段失败。

一、在目标电脑本地进入 MySQL

    mysql -u root -p

密码提示出现后再输入数据库管理员凭据，不要把密码附在命令行。进入 mysql> 后执行：

    SOURCE /实际解压路径/mysql/01-确认应用账号授权.sql;

随包 SQL 只执行 GRANT 和 SHOW GRANTS，不会创建账号，也不会修改既有密码。

二、核对授权范围

SHOW GRANTS 必须确认 personnel_archive@127.0.0.1 对 `personnel_archive`.* 拥有授权。
账号主机必须是 127.0.0.1，不应改为可从任意地址连接的通配主机。GRANT 立即生效，
无需再执行 FLUSH PRIVILEGES。

同一个应用数据源同时负责 Flyway V1—V15 和业务读写，因此该库内需要建表、改表、
索引、查询和写入权限；不要给应用账号 MySQL 全局权限，也不要让服务使用 root。

三、固定密码注意事项

本次 JAR 的 prod 配置已固定为你提供的应用账号密码。不要执行会随机更改该账号密码的
SQL，否则数据库会与 JAR 不一致而无法启动。不要把密码粘贴到聊天、保存到普通文本文
件、写进运维命令输出或截图。

以后如果确实需要修改数据库密码，必须同时修改项目的 application-prod.yml，重新执行
Java 21 完整测试并重新制作 JAR/离线包。仅重复运行 install.sh 不会修改 JAR 内配置。

四、执行顺序

1. 在目标 MySQL 执行随包授权 SQL并核对 SHOW GRANTS。
2. 执行 sudo ./install.sh。
3. 确认服务 active、18080 已监听。
4. 按 03 文档确认 flyway_schema_history 最终 version 为 15 且 success 为 1。
