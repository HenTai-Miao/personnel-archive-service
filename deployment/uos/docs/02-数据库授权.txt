人员档案数据服务——MySQL 密码轮换与授权
==========================================

为什么必须执行

旧的应用数据库随机密码曾保存在普通文本中，因此必须视为已暴露。项目首次启动还
要由 Flyway 建表并依次执行 V1—V14；如果应用账号没有 personnel_archive 库的
权限，服务会在启动阶段失败。

一、在目标电脑本地进入 MySQL

    mysql -u root -p

密码提示出现后再输入数据库管理员凭据，命令行中不要附带密码。进入 mysql> 后，
执行离线目录内的 SQL 文件；把下面示例路径换成目标电脑的真实绝对路径：

    SOURCE /实际路径/mysql/01-轮换应用密码并授权.sql;

也可以在 mysql> 中逐条执行该文件里的 ALTER USER、GRANT 和 SHOW GRANTS。

二、立即接住新随机密码

ALTER USER 的结果会显示 personnel_archive@127.0.0.1 的新随机密码。只临时复制
这一项，随后直接运行 install.sh，在隐藏输入提示中粘贴两次。不要粘贴到聊天，
不要保存到普通文本文件，不要放入 application-prod.yml，不要写进脚本、命令行、
截图或安装说明。完成安装后清除剪贴板。

三、核对授权范围

SHOW GRANTS 的结果必须能确认该账号对 `personnel_archive`.* 拥有授权。账号主机
必须是 127.0.0.1，而不是可从任意地址连接的通配主机。SQL 已直接修改权限，
不需要另外执行 FLUSH PRIVILEGES。

本项目用同一应用数据源完成 Flyway V1—V14 和业务读写，因此该库内需要建表、
改表、索引、查询和写入权限。不要给应用账号 MySQL 全局权限，也不要把数据库
管理员账号写入服务配置。

四、执行顺序

1. 停止正在使用旧密码的人员档案服务（首次安装可跳过）。
2. 执行随包 SQL，轮换密码并检查授权。
3. 首次安装运行 sudo ./install.sh；已有安装运行 sudo ./install.sh --reconfigure。
4. 确认服务 active，并按 03 文档检查 flyway_schema_history 的 version 14。

--reconfigure 只替换数据库密码，会保留 token pepper、身份字段 HMAC 密钥和
身份字段 AES 密钥。不要为已有数据库重新生成这三项密钥。
