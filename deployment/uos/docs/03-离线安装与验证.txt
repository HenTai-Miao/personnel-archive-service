人员档案数据服务——离线安装与验证
==================================

一、确认目录校验成功

进入解压后的离线目录，先执行：

    sha256sum --check SHA256SUMS
    chmod +x install.sh

所有条目必须显示 OK。然后确认已经按 02 文档轮换 MySQL 应用密码并完成授权。

二、首次安装

    sudo ./install.sh

安装器按 10 个步骤检查 Java 21、systemd、2 GiB 可用空间、包内校验、服务账号、
配置权限、日志目录、服务启动和 18080 端口。数据库密码会隐藏输入两次；三项安全
密钥由目标电脑上的 openssl 随机生成，不会显示或写入日志。

安装结果固定为：

    /opt/personnel-archive-service/personnel-archive-service.jar
    /opt/personnel-archive-service/log/personnel-archive-service.log
    /opt/personnel-archive-service/log/install-时间.随机值.log
    /etc/personnel-archive-service/personnel-archive-service.env
    /etc/systemd/system/personnel-archive-service.service

环境配置归 root:root、权限 0600；服务以无登录权限的 personnel-archive 专用用户
运行。不要用 root 身份手工运行 JAR。

三、两种可选模式

只安装文件、不在本次执行中启用或启动：

    sudo ./install.sh --no-start

核对完成后启用并启动：

    sudo systemctl enable --now personnel-archive-service.service

MySQL 应用密码以后再次轮换时：

    sudo ./install.sh --reconfigure

普通重复执行 sudo ./install.sh 会更新 JAR 和 service 文件，但原数据库密码、三项
安全密钥和历史日志全部保留。--reconfigure 会备份原环境配置，只更换数据库密码，
不会改变三项密钥。

四、服务和日志验证

    systemctl is-active personnel-archive-service.service
    systemctl status personnel-archive-service.service --no-pager
    ss -ltn | grep ':18080'
    ls -ld /opt/personnel-archive-service/log
    tail -n 100 /opt/personnel-archive-service/log/personnel-archive-service.log
    journalctl -u personnel-archive-service.service -n 100 --no-pager

状态应为 active，18080 应处于监听，文件日志中应看到 prod、Java 版本、数据库目标
127.0.0.1:3306/personnel_archive、Flyway 结果和服务启动检查点。日志只显示必要安全
密钥“已配置/未配置”，绝不能显示密钥值或数据库密码。

五、Flyway V1—V14 验证

以数据库管理员身份交互登录：

    mysql -u root -p

然后执行：

    USE personnel_archive;
    SELECT installed_rank, version, description, success
      FROM flyway_schema_history
     ORDER BY installed_rank;
    SELECT version, success
      FROM flyway_schema_history
     WHERE version = '14';

最终必须存在 version 14 且 success 为 1。首次空库应由服务自动完成 V1—V14；
不要手工创建业务表，不要修改 flyway_schema_history，也不要把其他数据库产品的
表直接复制进来冒充迁移结果。

六、客户端连接

服务端口默认是 18080。只在公司内部受控网络开放客户端实际需要的访问，MySQL
3306 保持仅本机使用。客户端 API 基地址应指向这台服务电脑的内部地址和 18080，
而不是直接连接 MySQL。
