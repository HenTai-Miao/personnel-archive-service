人员档案数据服务——离线安装与验证
==================================

一、确认目录校验成功

进入解压后的离线目录执行：

    sha256sum --check SHA256SUMS
    chmod +x install.sh start-prod.sh

所有条目必须显示 OK。随后确认 /data 已存在，并已按 02-数据库授权.txt 完成 GRANT 与
SHOW GRANTS 核对。

二、首次安装

    sudo ./install.sh

安装器按 9 个步骤检查包完整性、Java 21、systemd、/data 初始空间、服务账号、日志目录、
服务启动和 18080 端口。数据库连接和三项安全值已经固定在 prod 并包含在 JAR 中，安装器
不会询问、生成或另外保存这些值。

安装结果固定为：

    /data/personnel-archive-service/personnel-archive-service.jar
    /data/personnel-archive-service/log/log.YYYY-MM-DD.log
    /data/personnel-archive-service/log/install-时间.随机值.log
    /etc/systemd/system/personnel-archive-service.service

服务以无登录权限的 personnel-archive 专用用户运行。不要用 root 身份手工执行 JAR，
也不要从解压目录直接运行 JAR。

三、只安装或独立启动

只安装文件、不在本次执行中启用或启动：

    sudo ./install.sh --no-start

安装完成后可使用包内脚本：

    sudo ./start-prod.sh

如果不传完整安装包，首次部署只需要把下面两个文件放到固定目录：

    /data/personnel-archive-service/personnel-archive-service.jar
    /data/personnel-archive-service/启动prod环境.sh

然后赋权并执行：

    cd /data/personnel-archive-service
    chmod +x 启动prod环境.sh
    sudo ./启动prod环境.sh

脚本会检查 Java 21，创建专用服务账号和 log 目录，安装或更新 systemd 服务单元，并启动
或重启指定 JAR，不需要先运行 install.sh，也不需要外部环境文件。普通重复执行 install.sh
会更新 JAR 和服务单元并保留全部历史日志；三项安全值随同一个生产 JAR 永久固定。

四、服务和日志验证

    systemctl is-active personnel-archive-service.service
    systemctl status personnel-archive-service.service --no-pager
    ss -ltn | grep ':18080'
    ls -ld /data/personnel-archive-service/log
    tail -n 100 /data/personnel-archive-service/log/log.$(date +%F).log
    journalctl -u personnel-archive-service.service -n 100 --no-pager

状态应为 active，18080 应监听。应用每天直接写一份 `log.YYYY-MM-DD.log` 纯文本日志，
不压缩、不按大小分片，也不自动删除。文件日志应看到 prod、Java 版本、日志路径、数据库目标
127.0.0.1:3306/personnel_archive、数据库连接、Flyway 和服务就绪检查点。安全密钥只
记录“已配置/未配置”，不能出现值；日志也不能出现数据库密码。

五、Flyway V1—V14 验证

以数据库管理员身份交互登录：

    mysql -u root -p

然后执行：

    USE personnel_archive;
    SELECT installed_rank, version, description, success
      FROM flyway_schema_history
     ORDER BY installed_rank;
    SELECT version, success
      FROM flyway_schema_history
     WHERE version = '14';

最终必须存在 version 14 且 success 为 1。首次空库由服务自动完成 V1—V14；不要手工
创建业务表、修改 flyway_schema_history 或复制其他数据库的表冒充迁移结果。

六、客户端连接

服务端口是 18080。只在公司内部受控网络开放客户端需要的访问，MySQL 3306 保持仅本机
使用。客户端 API 基地址应指向这台服务电脑的内部地址和 18080，不能直接连接 MySQL。
